## 支付验证核心流程

支付验证流程始于对 `_callToolParams` 的 `_meta` 字段进行解析，提取 `x402/payment` 数据。该流程通过 `json.Marshal` 和 `json.Unmarshal` 实现类型转换与结构化解析，确保支付数据的正确性和完整性。整个流程在 `X402Handler.ServeHTTP` 方法中实现，拦截 POST 请求并检查是否为工具调用。

## 数据结构与类型转换

系统定义了关键的数据结构 `PaymentPayload` 和 `PaymentRequirement`，用于表示支付载荷和支付需求。`PaymentPayload` 包含版本、方案、网络和授权信息，而 `PaymentRequirement` 定义了支付所需的方案、网络、最大金额等属性。类型转换通过 `json.Marshal` 将任意数据转换为字节流，再通过 `json.Unmarshal` 解析为具体结构体。

## 支付需求匹配算法

`findMatchingRequirement` 算法根据 `payment.Network` 和 `payment.Scheme` 匹配对应的 `PaymentRequirement`。该算法支持通配符匹配与精确匹配策略，优先匹配网络和方案都符合的支付需求。如果未找到匹配项，则返回错误。

```mermaid
flowchart TD
Start([开始]) --> CheckNetwork["检查网络匹配"]
CheckNetwork --> NetworkMatch{"网络匹配?"}
NetworkMatch --> |否| Continue["继续下一个需求"]
NetworkMatch --> |是| CheckScheme["检查方案匹配"]
CheckScheme --> SchemeMatch{"方案匹配?"}
SchemeMatch --> |否| Continue
SchemeMatch --> |是| ReturnMatch["返回匹配的需求"]
Continue --> HasMore{"还有更多需求?"}
HasMore --> |是| CheckNetwork
HasMore --> |否| ReturnError["返回无匹配错误"]
ReturnMatch --> End([结束])
ReturnError --> End
```

## 链下验证机制

`facilitator.Verify` 接口在链下验证中起关键作用，包括上下文传递、签名验证和授权检查。验证过程通过 HTTP 请求发送到指定的 `facilitatorURL`，确保支付的合法性和有效性。验证成功后，系统会继续处理支付结算。

```mermaid
sequenceDiagram
participant Client as "客户端"
participant Handler as "X402Handler"
participant Facilitator as "Facilitator"
Client->>Handler : 发送包含支付的请求
Handler->>Handler : 解析支付数据
Handler->>Facilitator : 调用Verify接口
Facilitator-->>Handler : 返回验证结果
Handler->>Client : 根据结果返回响应
```

## 错误处理与传播

当验证失败时，如金额不足或网络不匹配，系统会构造 `sendInvalidParamsError` 并传播错误。错误信息通过 JSON-RPC 错误响应返回，确保客户端能够正确处理异常情况。

```mermaid
flowchart TD
Start([开始]) --> CheckPayment["检查支付数据"]
CheckPayment --> IsValid{"支付有效?"}
IsValid --> |否| ConstructError["构造sendInvalidParamsError"]
ConstructError --> SendError["发送错误响应"]
IsValid --> |是| ProcessPayment["处理支付"]
ProcessPayment --> SendSuccess["发送成功响应"]
SendError --> End([结束])
SendSuccess --> End
```
