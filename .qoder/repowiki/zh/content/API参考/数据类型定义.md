## PaymentRequirement 支付要求

`PaymentRequirement` 结构体表示服务器提供的支付方式，用于在支付协商过程中定义支付条件。该结构体的每个字段都具有特定的业务含义和约束条件。

- **scheme** (`string`): 支付方案，如 "exact" 表示精确金额支付。该字段用于匹配客户端支持的支付方案。
- **network** (`string`): 支付网络，如 "base" 或 "base-sepolia"。用于指定交易所在的区块链网络。
- **maxAmountRequired** (`string`): 所需最大支付金额，以字符串形式表示的大整数。金额必须为正数，且客户端在支付前会验证该值的有效性。
- **asset** (`string`): 支付资产的合约地址，如 USDC 在 Base 网络上的地址 `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`。
- **payTo** (`string`): 收款方地址，即支付授权中的 `to` 字段，指定资金接收方。
- **resource** (`string`): 资源标识符，通常格式为 `mcp://tools/{toolName}`，用于标识支付所访问的资源。
- **description** (`string`): 支付描述，提供关于支付目的的可读信息。
- **mimeType** (`string`, 可选): 响应的 MIME 类型，通常为 "application/json"。
- **outputSchema** (`interface{}`, 可选): 响应数据的 JSON Schema，用于描述返回数据的结构。
- **maxTimeoutSeconds** (`int`): 支付授权的最大超时时间（秒），默认至少 60 秒，最多 3600 秒。
- **extra** (`map[string]string`, 可选): 额外信息，包含资产名称（`name`）和版本（`version`）等元数据。

**JSON 序列化示例**:
```json
{
  "scheme": "exact",
  "network": "base",
  "maxAmountRequired": "1000",
  "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
  "payTo": "0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb6",
  "resource": "mcp://tools/paid-tool",
  "description": "Access to premium tool",
  "mimeType": "application/json",
  "maxTimeoutSeconds": 60,
  "extra": {
    "name": "USD Coin",
    "version": "2"
  }
}
```

**业务规则**:
- 金额必须为正数，否则支付将被拒绝。
- `maxTimeoutSeconds` 会被限制在 60 到 3600 秒之间。
- 支付协商时，客户端会根据 `network` 和 `asset` 匹配其配置的支付选项。

## PaymentPayload 支付载荷

`PaymentPayload` 结构体表示通过 `X-PAYMENT` 头部发送的已签名支付信息。它包含支付的元数据和授权数据。

- **x402Version** (`int`): x402 协议版本，当前为 1。
- **scheme** (`string`): 支付方案，与 `PaymentRequirement` 中的 `scheme` 字段匹配。
- **network** (`string`): 支付网络，与 `PaymentRequirement` 中的 `network` 字段匹配。
- **payload** (`PaymentPayloadData`): 包含签名和授权数据的嵌套结构。

`PaymentPayloadData` 结构体包含以下字段：
- **signature** (`string`): EIP-712 类型数据的签名，以 `0x` 开头的十六进制字符串。
- **authorization** (`PaymentAuthorization`): EIP-3009 授权数据。

`PaymentAuthorization` 结构体包含 EIP-3009 授权的核心字段：
- **from** (`string`): 付款方地址，即签名者的地址。
- **to** (`string`): 收款方地址，与 `PaymentRequirement.PayTo` 一致。
- **value** (`string`): 支付金额，以字符串形式表示的大整数。
- **validAfter** (`string`): 授权生效时间戳（Unix 秒），允许一定的时钟偏差（默认 30 秒）。
- **validBefore** (`string`): 授权失效时间戳（Unix 秒），基于 `maxTimeoutSeconds` 计算。
- **nonce** (`string`): 唯一的随机数，通过 `Keccak256` 哈希生成，确保每次支付的唯一性。

**编码方法**:
`Encode` 方法将 `PaymentPayload` 结构体序列化为 JSON，然后进行 Base64 编码，生成 `X-PAYMENT` 头部的值。该方法不处理错误，假设 JSON 序列化和 Base64 编码总是成功。

**JSON 序列化示例**:
```json
{
  "x402Version": 1,
  "scheme": "exact",
  "network": "base",
  "payload": {
    "signature": "0x...",
    "authorization": {
      "from": "0x...",
      "to": "0x...",
      "value": "1000",
      "validAfter": "1700000000",
      "validBefore": "1700000060",
      "nonce": "0x..."
    }
  }
}
```

## PaymentRequirementsResponse 支付要求响应

`PaymentRequirementsResponse` 结构体作为 HTTP 402 响应体的结构规范，用于在需要支付时向客户端提供支付选项。

- **x402Version** (`int`): x402 协议版本，当前为 1。
- **error** (`string`): 错误消息，通常为 "Payment required to access this resource"。
- **accepts** (`[]PaymentRequirement`): 服务器接受的支付要求列表，客户端需从中选择一个进行支付。

该结构体在服务器端通过 `sendPaymentRequiredError` 方法生成，将 `PaymentRequirement` 列表嵌入 JSON-RPC 402 错误的 `data` 字段中。

**JSON 序列化示例**:
```json
{
  "x402Version": 1,
  "error": "Payment required to access this resource",
  "accepts": [
    {
      "scheme": "exact",
      "network": "base",
      "maxAmountRequired": "1000",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "payTo": "0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb6",
      "resource": "mcp://tools/paid-tool",
      "description": "Access to premium tool",
      "mimeType": "application/json",
      "maxTimeoutSeconds": 60,
      "extra": {
        "name": "USD Coin",
        "version": "2"
      }
    }
  ]
}
```

## SettlementResponse 结算响应

`SettlementResponse` 结构体表示交易确认后的反馈格式，用于通知客户端支付结算的结果。

- **success** (`bool`): 结算是否成功。
- **transaction** (`string`): 成功结算的交易哈希。
- **network** (`string`): 交易所在的网络。
- **payer** (`string`): 付款方地址。
- **errorReason** (`string`, 可选): 结算失败的原因。

该响应通过 `X-PAYMENT-RESPONSE` 头部或 JSON-RPC 响应的 `result._meta` 字段返回给客户端。在服务器端，`forwardWithSettlementResponse` 方法负责将结算响应注入到最终的 JSON-RPC 响应中。

**JSON 序列化示例**:
```json
{
  "success": true,
  "transaction": "0x...",
  "network": "base",
  "payer": "0x...",
  "errorReason": ""
}
```

## PaymentEvent 支付事件

`PaymentEvent` 结构体表示支付生命周期中的事件，用于记录支付尝试、成功和失败的状态。

- **type** (`PaymentEventType`): 事件类型，包括 `attempt`、`success`、`failure`。
- **resource** (`string`): 支付关联的资源。
- **method** (`string`): 触发支付的请求方法。
- **amount** (`*big.Int`): 支付金额。
- **network** (`string`): 支付网络。
- **asset** (`string`): 支付资产。
- **recipient** (`string`): 收款方地址。
- **transaction** (`string`): 交易哈希（仅在成功时填充）。
- **error** (`error`): 错误信息（仅在失败时填充）。
- **timestamp** (`int64`): 事件发生的时间戳（Unix 秒）。

`PaymentEventType` 是一个字符串常量，定义了三种生命周期类型：
- `PaymentEventAttempt`: 支付尝试。
- `PaymentEventSuccess`: 支付成功。
- `PaymentEventFailure`: 支付失败。

**业务规则**:
- 事件通过 `recordPaymentEvent` 和 `recordPaymentError` 方法记录。
- `PaymentRecorder` 用于在测试中收集和验证支付事件。

## ClientPaymentOption 客户端支付选项

`ClientPaymentOption` 结构体表示客户端接受的支付方式，它扩展了 `PaymentRequirement` 并添加了客户端特定的字段。

- **Priority** (`int`): 优先级，数值越低优先级越高。用于在多个可选支付方式中选择最优方案。
- **MaxAmount** (`string`): 客户端愿意为此选项支付的最大金额。如果服务器要求的金额超过此值，该选项将被跳过。
- **MinBalance** (`string`): 最小余额，当账户余额低于此值时不应使用此选项。
- **ChainID** (`*big.Int`): 签名所用的链 ID，是内部必需字段。如果未配置，签名将失败。

**设计目的**:
- `Priority` 和 `MaxAmount` 允许客户端根据自身策略选择支付方式。
- `ChainID` 确保签名在正确的网络上有效，防止跨链签名错误。

**使用限制**:
- `ChainID` 必须配置，否则 `SignPayment` 将返回错误。
- `MaxAmount` 用于限制支付金额，保护客户端免受高额支付要求的影响。

**Fluent API**:
`client_options.go` 提供了 `WithPriority`、`WithMaxAmount`、`WithMinBalance` 等方法，允许链式调用以方便地配置支付选项。
