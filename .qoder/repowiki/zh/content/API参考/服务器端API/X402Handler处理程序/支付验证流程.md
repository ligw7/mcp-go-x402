## 引言
本文档深入解析X402Handler中支付验证的核心流程。该流程实现了x402协议的支付验证机制，通过拦截MCP工具调用请求，检查并验证支付信息，确保资源访问的安全性和合规性。文档将详细说明从请求中提取支付数据、匹配支付要求、与Facilitator组件交互验证以及错误处理的完整链条。

## 支付验证核心流程

### 请求拦截与支付提取
`X402Handler.ServeHTTP`方法拦截POST请求，解析JSON-RPC格式的工具调用。当检测到需要支付的工具时，从请求参数的`_meta`字段中提取`x402/payment`数据。

```mermaid
flowchart TD
A[接收HTTP请求] --> B{是否为POST方法?}
B --> |否| C[直接转发]
B --> |是| D[读取请求体]
D --> E[解析JSON-RPC请求]
E --> F{是否为tools/call?}
F --> |否| C
F --> |是| G[解析工具名称]
G --> H[查找支付要求]
H --> I{需要支付?}
I --> |否| C
I --> |是| J[检查_meta字段]
J --> K{存在x402/payment?}
K --> |否| L[返回402错误]
K --> |是| M[解析支付载荷]
M --> N[匹配支付要求]
```

## 与Facilitator组件交互

### Verify接口调用
当支付载荷成功匹配要求后，`X402Handler`调用`Facilitator.Verify`接口进行链上验证。

```mermaid
sequenceDiagram
participant Handler as X402Handler
participant Facilitator as Facilitator
participant Chain as 区块链
Handler->>Facilitator : Verify(payment, requirement)
Facilitator->>Chain : 验证支付有效性
Chain-->>Facilitator : 返回验证结果
Facilitator-->>Handler : VerifyResponse
Handler->>Handler : 处理验证结果
```

## 错误处理机制

### 错误反馈类型
系统定义了多种错误反馈机制：

| 错误类型 | HTTP状态码 | JSON-RPC错误码 | 触发条件 |
|--------|----------|-------------|--------|
| 支付要求 | 200 | 402 | 未提供支付信息 |
| 参数无效 | 200 | -32602 | 支付数据解析失败 |
| 内部错误 | 200 | -32603 | 验证服务调用失败 |

**Section sources**
- [server/handler.go](file://server/handler.go#L217-L267)

### InvalidReason传递

## 完整流程时序图

```mermaid
sequenceDiagram
participant Client as 客户端
participant Handler as X402Handler
participant Facilitator as Facilitator
participant MCP as MCP处理器
Client->>Handler : 发送工具调用请求
Handler->>Handler : 解析请求，检查支付要求
alt 无支付信息
Handler->>Client : 返回402错误及支付要求
else 有支付信息
Handler->>Handler : 解析PaymentPayload
Handler->>Handler : 调用findMatchingRequirement
alt 匹配失败
Handler->>Client : 返回无效参数错误
else 匹配成功
Handler->>Facilitator : 调用Verify接口
Facilitator->>Facilitator : 验证链上支付
Facilitator-->>Handler : 返回验证结果
alt 验证失败
Handler->>Client : 返回验证失败错误
else 验证成功
Handler->>Facilitator : 调用Settle接口
Facilitator->>Facilitator : 执行链上结算
Facilitator-->>Handler : 返回结算结果
Handler->>MCP : 转发请求
MCP-->>Handler : 返回响应
Handler->>Handler : 添加结算响应到_meta
Handler-->>Client : 返回最终响应
end
end
end
```
