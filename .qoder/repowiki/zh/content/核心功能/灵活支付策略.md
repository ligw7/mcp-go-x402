## 简介

## 支付要求配置

`PaymentRequirement`结构定义了资源或工具的支付要求，包含网络、资产、金额、收款地址等关键字段。通过`AddPayableTool`方法，可以将支付要求与特定工具关联，实现灵活的定价策略。

```mermaid

}
class Config {
+string FacilitatorURL
+map[string][]PaymentRequirement PaymentTools

+bool Verbose
```

## 多选项支付支持

系统支持为单个工具配置多个支付选项，允许用户选择不同的支付方式。通过在`AddPayableTool`方法中传入多个`PaymentRequirement`参数，可以实现多选项支付功能。

```mermaid
flowchart TD
Start([开始]) --> CheckPayment["检查支付信息"]
CheckPayment --> HasPayment{"支付信息存在?"}
HasPayment --> |否| Send402["发送402错误"]
Send402 --> ShowOptions["显示支付选项"]
ShowOptions --> Option1["选项1: USDC on Base"]
ShowOptions --> Option2["选项2: ETH on Ethereum"]
ShowOptions --> OptionN["选项N: ..."]
HasPayment --> |是| VerifyPayment["验证支付"]
VerifyPayment --> MatchRequirement["匹配支付要求"]
MatchRequirement --> |成功| ProcessRequest["处理请求"]
MatchRequirement --> |失败| RejectPayment["拒绝支付"]
ProcessRequest --> End([结束])
RejectPayment --> End
Send402 --> End
```

## 支付验证流程

支付验证流程由`X402Handler`处理，包括支付信息检查、要求匹配、第三方验证和结算等步骤。系统通过`findMatchingRequirement`方法查找匹配的支付要求，并通过`Facilitator`接口与外部服务进行验证和结算。

```mermaid
sequenceDiagram
participant Client as "客户端"
participant Handler as "X402Handler"
participant Facilitator as "支付协调器"
Client->>Handler : 发送工具调用请求
Handler->>Handler : 检查是否需要支付
alt 无需支付
Handler->>Client : 直接处理请求
else 需要支付
Handler->>Handler : 检查支付信息
alt 无支付信息
Handler->>Client : 返回402错误及支付选项
else 有支付信息
Handler->>Handler : 解析支付数据
Handler->>Handler : 匹配支付要求
Handler->>Facilitator : 验证支付
Facilitator-->>Handler : 返回验证结果
alt 验证失败
Handler->>Client : 返回支付验证失败
else 验证成功
Handler->>Facilitator : 结算支付
Facilitator-->>Handler : 返回结算结果
Handler->>Client : 处理请求并返回结果
end
end
end
```
